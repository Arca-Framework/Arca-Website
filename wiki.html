Introduction

Arca is a modern, lightweight framework for FiveM roleplay servers.

Everything goes through arca_core, the same way qb-core or qbx_core work. You grab the core object once and use it for players, callbacks, notifications and UI.

local Arca = exports.arca_core:GetCoreObject()

Installation

Set up a complete Arca server using the official txAdmin recipe.

Info
  • We highly recommend using txAdmin to install your server. The recipe downloads every resource, creates the database tables and writes your server.cfg.
  • Prefer to do it by hand? See Manual installation.
XAMPP is not supported
  • Install MariaDB directly from mariadb.org.
  • Minimum: MariaDB 10.6 · Recommended: the latest LTS release.
  • Remember the root password you set during setup, txAdmin will ask for it.

Installation steps

  1. Download the server

    Download the latest recommended Windows artifact from the FiveM artifacts page. On Linux, use the Linux artifacts.

  2. Extract the artifacts

    Create a folder such as C:\FXServer\server and extract the archive into it. Keep your server data in a separate folder, for example C:\FXServer\arca.

  3. Start the server

    Run FXServer.exe. A console window opens and shows a txAdmin link and a PIN. Open the link in your browser, enter the PIN and link your Cfx.re account.

  4. Start the recipe installation

    In the setup wizard, pick a server name, then choose Popular Recipes → Remote URL Template and paste the Arca recipe URL:

    https://raw.githubusercontent.com/Arca-Framework/txAdmin-recipe/main/recipe.yaml

    Choose the folder for your server data (e.g. C:\FXServer\arca).

  5. Deploy the recipe

    Enter your Cfx.re license key and your MariaDB details (host localhost, user root, your password, database name arca). Click Run Recipe and wait for every task to finish.

  6. Run the server

    Click Save & Run Server. Connect with FiveM (F8 → connect localhost) and create your first character.

Manual installation

Install Arca on an existing server without txAdmin's recipe.

1. Download the resources

Download each repository and place it in your resources folder. Folder names must match exactly.

resources/
├─ [standalone]/
│  ├─ oxmysql/
│  ├─ ox_lib/                 (only needed for illenium-appearance)
│  └─ illenium-appearance/    (optional)
└─ [arca]/
   ├─ arca_core/
   ├─ arca_target/
   └─ arca_character/

2. Create the database

Create a database called arca and run arca_core/sql/arca.sql in HeidiSQL (or any SQL client).

3. Configure server.cfg

Order matters, dependencies must start before the resources that use them.

set mysql_connection_string "mysql://root:password@localhost/arca?charset=utf8mb4"

ensure oxmysql
ensure arca_core
ensure arca_target
ensure ox_lib
ensure illenium-appearance
ensure arca_character
ensure arca_gangs   # player-made gangs (creates its table on first start)

add_ace group.admin arca.god allow
Warning

Do not run qb-core or qb-multicharacter alongside Arca. arca_core already answers as qb-core, see qb-core bridge.

Permissions

Arca uses FiveM's built-in ACE system.

Each level in Config.Server.Permissions maps to an ace called arca.<level>. Levels are ordered highest first, and a higher level includes every level below it.

AceHas access to
arca.godgod, admin, mod
arca.adminadmin, mod
arca.modmod
 
# give the group a level
add_ace group.admin arca.admin allow
add_ace group.mod arca.mod allow

# put a player in a group
add_principal identifier.license:abc123 group.admin

Check a permission in code:

if Arca.Functions.HasPermission(source, 'admin') then
    -- source is admin or god
end

Your first resource

A complete, working Arca script in three files: a car wash with a target zone, a fee and a progress bar.

1. The folder

my_carwash/
├─ fxmanifest.lua
├─ client.lua
└─ server.lua

2. fxmanifest.lua

fx_version 'cerulean'
game 'gta5'
lua54 'yes'

-- gives every file a global `Arca` (the core object)
shared_script '@arca_core/shared/import.lua'

client_script 'client.lua'
server_script 'server.lua'

dependencies { 'arca_core', 'arca_target' }

No import? Put local Arca = exports.arca_core:GetCoreObject() at the top of each file instead.

3. server.lua

The server owns money and decides. Never trust the client for prices or rewards.

local PRICE = 50
local WASH = vector3(26.5, -1392.0, 29.3)

-- the client asks "can I wash?"; the server checks and takes the money
Arca.Callback.Register('my_carwash:pay', function(source)
    local player = Arca.Functions.GetPlayer(source)
    if not player then return false end

    -- are they actually at the car wash?
    local coords = GetEntityCoords(GetPlayerPed(source))
    if #(coords - WASH) > 10.0 then return false end

    if not player.RemoveMoney('cash', PRICE, 'car wash') then
        Arca.Notify(source, ('You need $%d cash'):format(PRICE), 'error')
        return false
    end
    return true
end)

4. client.lua

local WASH = vector3(26.5, -1392.0, 29.3)

local function wash()
    local veh = GetVehiclePedIsIn(PlayerPedId(), false)
    if veh == 0 then return Arca.Notify('Drive in first', 'error') end

    if not Arca.Callback.Await('my_carwash:pay') then return end

    local done = Arca.Progress({
        label = 'Washing vehicle',
        duration = 6000,
        canCancel = false,
        disable = { car = true },
    })
    if done then
        SetVehicleDirtLevel(veh, 0.0)
        WashDecalsFromVehicle(veh, 1.0)
        Arca.Notify('Squeaky clean!', 'success')
    end
end

-- third-eye option on the wash bay
exports.arca_target:addSphereZone({
    name = 'my_carwash',
    coords = WASH,
    radius = 4.0,
    options = {
        { name = 'my_carwash:wash', label = 'Wash vehicle ($50)', icon = 'fa-solid fa-soap', onSelect = wash },
    },
})

-- a blip so players can find it
CreateThread(function()
    local blip = AddBlipForCoord(WASH.x, WASH.y, WASH.z)
    SetBlipSprite(blip, 100)
    SetBlipAsShortRange(blip, true)
    BeginTextCommandSetBlipName('STRING')
    AddTextComponentSubstringPlayerName('Car Wash')
    EndTextCommandSetBlipName(blip)
end)

5. Start it

ensure my_carwash

Make sure it starts after arca_core and arca_target. Restart it live with restart my_carwash in the server console.

The pattern every Arca script follows

  1. Client shows things: target options, menus, progress bars, notifications.
  2. Server decides: checks distance, job, items and money, then changes them.
  3. They talk with callbacks (when the client needs an answer) or events (fire and forget).

Troubleshooting

Fixes for the most common problems.

Stuck on a black screen when joining

  • Make sure arca_character is started and shows no errors in F8 or the server console.
  • Make sure arca_core starts before arca_character.
  • Check that no other multicharacter resource (like qb-multicharacter) is running.

"No Rockstar license found"

Arca needs a Rockstar license identifier. Restart FiveM, make sure you are signed in to the Rockstar launcher, and try again.

Database errors

  • Check mysql_connection_string in server.cfg (user, password, database name).
  • Make sure arca.sql was run, the players table must exist.
  • Use MariaDB, not XAMPP or MySQL 5.

illenium-appearance doesn't save clothes

  • Use the Arca fork of illenium-appearance, it detects Arca natively.
  • Start arca_core before illenium-appearance (the recipe already does).

"Table 'player_outfits' doesn't exist"

illenium's outfit tables were never created. The Arca fork creates them on start; on an older copy, run the four files in illenium-appearance/sql/ on your database.

Weapons disappear when I take them out

With InvConfig.Weapons.StripUnknownWeapons on, any weapon that didn't come from the inventory is removed. Give weapons as items (/giveitem me weapon_pistol 1) instead of with natives or other scripts.

A qb resource doesn't work

Most qb resources work through the bridge. If one doesn't, check if it needs a qb resource Arca replaces: use arca_inventory for inventory, arca_target for targeting and the context menu for menus, or uses a rarely-used qb-core function. Arca can't fix third-party scripts, contact the script's author.

Radial or target key does nothing

Keys are registered as key mappings. If a player changed them, check Settings → Key Bindings → FiveM. Both only work once a character is loaded.

Callbacks

Ask the other side for data and wait for the answer.

Client → server

Arca.Callback.Register('garage:getVehicles', function(source, garage)
    local player = Arca.Functions.GetPlayer(source)
    return MySQL.query.await('SELECT * FROM vehicles WHERE citizenid = ?', { player.PlayerData.citizenid })
end)
-- waits for the result
local vehicles = Arca.Callback.Await('garage:getVehicles', 'legion')

-- or without waiting
Arca.Callback.Trigger('garage:getVehicles', function(vehicles)
    print(#vehicles)
end, 'legion')

Server → client

Arca.Callback.Register('admin:getCoords', function()
    return GetEntityCoords(PlayerPedId())
end)
-- name, target, timeout (ms, default 10000), ...args
local coords = Arca.Callback.Await('admin:getCoords', source, 5000)
Info
  • Callbacks can return multiple values.
  • If a callback errors or times out, Await returns nil. Client → server calls time out after 10s (a warning is printed in F8); server → client calls use the timeout you pass (default 10s).
  • Await blocks the current thread, call it inside an event handler, command or CreateThread.
  • Always validate arguments on the server, clients can send anything.

Jobs & gangs

Jobs are defined in arca_core/shared/jobs.lua. Gangs are made by players with arca_gangs.

Gangs

There is no gangs.lua any more. Players create gangs in-game and arca_gangs registers them with arca_core at runtime, so PlayerData.gang, SetGang, groups checks and QBCore.Shared.Gangs work exactly as before. The only built-in gang is none.

The format is the same as qb-core, so you can paste qb job files straight in. Grade keys are strings.

mechanic = {
    label = 'Mechanic',
    type = 'mechanic',
    defaultDuty = true,
    grades = {
        ['0'] = { name = 'Trainee', payment = 50 },
        ['1'] = { name = 'Mechanic', payment = 75 },
        ['2'] = { name = 'Owner', payment = 120, isboss = true },
    },
},

Multi-job & duty

A character can hold several jobs (ArcaConfig.Jobs.MaxJobs, default 3) and switch the active one. Only the active job counts for duty, paychecks, groups checks and PlayerData.job, so existing scripts keep working unchanged.

  • /jobs or the Jobs radial entry opens a menu to switch jobs, go on / off duty or clock out to civilian.
  • /duty toggles duty for the active job.
  • Admins: /addjob id job grade, /removejob id job. /setjob still makes a job active straight away (and adds it to their jobs).
  • Held jobs are stored in PlayerData.metadata.jobs as { police = 2, mechanic = 0 }.
ArcaConfig.Jobs = {
    MaxJobs = 3,                -- jobs one character can hold
    DutyOnSwitch = false,       -- go on duty when switching jobs
    RespectDefaultDuty = true,  -- ...unless the job has defaultDuty = true
}

Player methods

player.AddJob(name, grade)

Hold a job without switching to it. Returns false, reason if the job doesn't exist or they hold too many.

player.RemoveJob(name)

Stop holding it. If it was active they switch to their next job (or civilian).

player.SwitchJob(name)

Make a held job active ('unemployed' clocks out).

player.GetJobs()

List of { name, label, grade, gradeName, payment, isboss, active }.

player.HoldsJob(name, minGrade?)

Do they hold this job at all (not only the active one)?

Conventions

How Arca resources agree on shared state, so your scripts fit in with everything else.

What Arca doesn't ship yet

There is no Arca vehicle keys, fuel or garage resource yet. If you build one, follow the conventions below so the HUD, inventory and admin menu work with it automatically. Death and EMS are handled by arca_health.

Checking jobs and duty

local player = Arca.Functions.GetPlayer(source)
local job = player.PlayerData.job
if job.name ~= 'police' or not job.onduty then return end
if job.grade.level < 2 then return end     -- sergeant and up
if job.isboss then ... end
if Arca.Functions.HasJob('police', true) then ... end   -- on duty only

Players can hold several jobs; checks use the active one. Use exports.arca_core:HoldsJob(source, name) to check any job they hold. arca_target and inventory shops/stashes take a groups table in the same shape: { police = 0, ambulance = 2 } = job (or gang) name → minimum grade.

Money

  • Always use player.AddMoney / RemoveMoney (server). Accounts: cash, bank, crypto.
  • RemoveMoney returns false when they can't afford it, check it before giving anything.
  • The inventory's cash item follows the cash balance by itself. Don't add or remove cash items for payments.
  • Pass a reason, it appears in the onMoneyChange events and in the player's arca_bank activity.
  • For job money, fines and shared accounts use arca_bank's exports (AddJobMoney, RemoveMoney('p:CID', ...)…).

Vehicles: spawning, keys and fuel

  • Spawned vehicles, when Arca spawns a vehicle for a player (/car, admin menu), it fires arca_core:client:vehicleSpawned with vehicle, plate. A keys script should listen to it and give keys.
  • Fuel, store fuel in the vehicle statebag Entity(vehicle).state.fuel (0–100). The HUD and admin refuel use it, falling back to GetVehicleFuelLevel.
  • Seatbelt, tell the HUD with TriggerEvent('seatbelt:client:ToggleSeatbelt', state) or exports.arca_hud:SetSeatbelt(state).
AddEventHandler('arca_core:client:vehicleSpawned', function(vehicle, plate)
    TriggerServerEvent('mykeys:give', plate)
end)

Entity(vehicle).state:set('fuel', 65.0, true)

Voice

The HUD reads LocalPlayer.state.proximity.index (voice range) and LocalPlayer.state.radioChannel, the statebags pma-voice uses.

Weather and time

Don't set weather or time directly, arca_admin keeps them in sync and will overwrite you. Use exports.arca_admin:SetWeather('RAIN') and SetTime(22, 0) on the server.

UI

  • Use Arca.Notify, Arca.Progress, Arca.ShowTextUI, the context menu and arca_target instead of shipping your own, so every script looks the same.
  • For custom NUI, match the theme: background #0d1114, panels #12171b, accent #00ff6a, text on accent #03140a, font Inter.

Naming

  • Prefix events and callbacks with your resource name: my_garage:server:takeOut, my_garage:getVehicles.
  • Never trust arguments from the client in a server event, re-check distance, job, items and money.

arca_character

Character selection and creation.

How it works

  1. When a player joins, the loading screen closes and the selection menu opens.
  2. They pick a character, or create one in an empty slot (name, birthdate, gender, nationality).
  3. The character spawns at their last position. New characters spawn at Config.Player.DefaultSpawn.
  4. /logout returns to the menu.

arca_spawn

Choose where to spawn after picking a character.

How it works

  1. After a player presses Play in arca_character, a camera opens high above the city.
  2. Clicking a location flies the camera there. ↑ / ↓ browse the list.
  3. Spawn here, Enter or clicking the selected card again dives the camera down and spawns the player.
  • Last location is offered first (where the character logged out).
  • Players who are downed or dead (arca_health) or still in jail (metadata.jailtime) only get Last location, so relogging can't skip death or a sentence.
  • New characters skip the selector: they spawn at ArcaConfig.Player.DefaultSpawn and go straight into the appearance editor.
  • The server keeps the coordinates and only accepts a location it offered that player.

arca_phone

An iFruit smartphone built around phone chips: calls, messages, a camera, Lifeinvader, FruitPay, Fleeca, DownTown Taxi, and your own apps.

Phone chips

A phone's number, contacts, messages, call history, photos, Lifeinvader profile and settings live on its chip, not on the phone or the character.

  • Every new phone (shops, /giveitem, the starter phone) comes with its own chip and a 555-#### number.
  • Right-click a phone in the inventory to see its chip, remove it (it becomes a phone_chip item) or insert one.
  • No chip = iFruit OS fails to boot: the loading bar stalls, the status bar shows No Chip with no signal or wifi. Whoever holds your phone can take your chip, and your number and messages with it.
  • Spare chips are sold at the Digital Den electronics stores.

arca_health

The medical core: last stand, death screen, injuries, bleeding, EMS and hospital respawns.

How it works

  1. Downed, at 0 health you go into last stand. Press G to call EMS. A timer counts down until you bleed out.
  2. Unconscious, after the timer (or with last stand off). Once DeathTime has passed, hold E to respawn at the nearest hospital for a fee.
  3. Revived, by EMS, an admin or a script, at any point.

The state is saved in metadata, so relogging doesn't get you out of it.

Injuries

  • Each hit is recorded per body part (head, torso, arms, legs) with severity 1–4, and the cause is worked out from the weapon (gunshot, stab, blunt force, fall, vehicle, burns…).
  • Bullets and blades cause bleeding, which drains health; heavy bleeding blurs the screen.
  • Leg injuries make you limp (no sprinting or jumping).
  • An arca_inventory bandage slows bleeding; a medikit stops it.

EMS

On-duty EMS (EMSJobs, default ambulance) get third-eye options on players: Revive, Treat wounds and Check injuries (state, likely cause, bleeding and every injured part). Pressing G sends EMS an alert with a flashing blip. When no EMS are on duty, players can pay at the hospital check-in desk.

arca_fuel

Fuel with a real nozzle and hose: grab it at the pump, fuel at the car's filler, put it back.

  1. Third-eye a pump › Grab nozzle. A hose runs back to the pump; walk more than the hose length away and it snaps back.

arca_mechanic

Mechanic job: customers preview upgrades, mechanics fit them with crafted parts, send invoices and run the shop. Also vehicle wear, mileage and seatbelts for everyone.

How a job works

  1. Preview: the customer drives onto a preview spot and presses E. They browse performance, body, wheels, paint, lights, interior and extras on their own vehicle, with a price estimate.
  2. Job sheet: saving gives them a mechanic_sheet item listing every change. Nothing is fitted yet; they hand the sheet to a mechanic.
  3. Fitting: an on-duty mechanic uses the sheet next to the vehicle inside the shop. Each change uses one part item and is saved to the vehicle in player_vehicles. From the sheet the mechanic can also send an invoice: the shop account gets the money, the mechanic a commission.
  4. Parts: every part is an item crafted at the shop's workbench from materials sold by the Parts Supplier (mechanics only). Recipes are in config.lua.
  5. Boss menu: hire people standing with you, change ranks, fire (offline staff too), deposit / withdraw from the shop's arca_bank job account.

Each shop also has a clock in / out point, a shared parts stash and a full repair (third-eye a vehicle in the shop, uses a repairkit).

Vehicle condition, mileage and seatbelts

Every vehicle has a condition per part (engine, oil, radiator, brakes, clutch, tyres, battery) and an odometer, kept in state bags and saved to player_vehicles (the condition and mileage columns are added automatically). Parts wear with distance, crashes, hard braking and high revs (MechConfig.Condition).

  • Worn parts light dash lamps in arca_hud (amber at Warn, red at Fail).
  • Failing parts mean less power, weaker brakes, less grip, stalling, burst tyres, a dead battery, overheating and oil leaks that can catch fire.
  • On-duty mechanics third-eye a vehicle → Inspect vehicle to see every part and the mileage, and service parts with engine_oil, coolant, brake_pads, clutch_kit, tyres, car_battery or engine_parts.
  • B toggles the seatbelt. Unbuckled occupants are thrown out in hard crashes; buckled ones can't get out until they unbuckle.

Adding a shop

  1. Add a job to arca_core/shared/jobs.lua (copy mechanic), with bank = { minGrade = n } if it needs a shop account.
  2. Copy the lscustoms block in locations.lua, set job and the positions (/coords in game).
  3. To sell materials there, add its job to the mech_supplies shop groups and a location in arca_inventory/shared/config.lua.

Exports

Client: GetVehicleStatus(vehicle), IsSeatbeltOn(). Server: GetCondition(vehicle), SetPartCondition(vehicle, part, value).

Requirements

Every setup has the same requirements block: job blacklist, gang only (with minimum rank), certain jobs, police on duty needed, a required item (optionally used up), cooldown (everyone / per gang / per player), opening hours, arca_skills levels or perks, extra skill XP on completion, and "secret" (hidden from players who don't qualify).

Corner selling

Third-eye a local → Sell drugs, pick a drug, amount and price. They take the deal, haggle with a counter-offer, walk off, or run and sometimes call the police. Which drugs locals buy and their price range are set in /illegal → Drugs → Corner selling. Selling in one spot too long makes the area go hot for a while.

Petty crime

Mugging (rob a local at gunpoint), pickpocketing, and breaking into mailboxes, parking meters and vending machines across the city. Each has its own loot, cooldowns, required item, police needed and dispatch alert, set in /illegal → Petty crime.

arca_skills

Skill trees: earn XP by doing things, level up sub-skills and spend skill tokens on perks along any path.

Open it with /skills or K. Drugs, Shooting, Driving, Selling and Stamina are built in. Each tree has branches (e.g. Drugs › Harvesting / The Bench / Dealing) with their own XP and level; every level gives skill tokens, shared across all trees. A perk can be unlocked when it links to one you have, its branch is high enough and you have the tokens (hold the mouse on it). Reset perks refunds every token. The skill_token item gives a token when used.

arca_emotes

Emotes, walk styles and facial expressions, with a full emote menu, quick slots and shared emotes.

ID cards and licences you show to the people around you, City Hall, and a Documents phone app with forms, sharing and drawn signatures.

Cards

ID cards and licences are inventory items. Use one to show it on screen to you and to everyone within 3 m (ShowDistance), with a short hand-over animation. It slides away after ShowTime seconds, or press Backspace.

City Hall

Third-eye the clerk at Los Santos City Hall to buy a new card or replace a lost one. Licences that have to be issued first (firearms, hunting, pilot) can only be replaced once you hold them; the driver licence grants the licence when bought (grants = true).

Documents app

  1. New document: pick a form: blank, vehicle bill of sale, employment contract, loan, lease, witness statement, and job-only forms like a police or medical report. Fields fill themselves in where they can (your name, today's date, your job, your number).
  2. Share it with someone standing next to you or with a phone number. Tick Ask them to sign it to send a signature request; it appears under To sign with a badge on the app icon.
  3. Sign by drawing your signature. Once anyone signs, the document is locked.
  4. Print a copy (document item). Using it shows the paper, signatures included, to the people around you.

Official forms are stamped with the author's job. Stored in arca_identity_documents, arca_identity_access and arca_identity_signatures (created on start).

qb-core bridge

Run resources made for qb-core on Arca.

arca_core declares provide 'qb-core', so resources that use exports['qb-core']:GetCoreObject() or dependency 'qb-core' talk to Arca instead. The QBCore object they get is the Arca object with qb-named functions added.

Third-party resources

Arca makes the bridge as complete as possible, but can't fix or support third-party scripts. If a qb resource doesn't work, contact its author.
